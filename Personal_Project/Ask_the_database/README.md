# Ask the Database

A natural-language-to-SQL assistant, plus a test harness that measures how often it is right.

Type a question such as *"Which restaurant had the highest revenue last month?"*. An AI model writes
the SQL, a safety guard validates it, the query runs read-only on a small SQLite database, and the
app shows the result table and the SQL it used. A separate evaluation script runs 20 questions with
known correct answers and reports accuracy, so prompt changes can be judged by numbers, not vibes.

All data is **synthetic** (generated by a script). Nothing here comes from a real company.

```
question
   │
   ▼
prompt (schema + rules + examples, versioned in prompts/)
   │
   ▼
AI model (Gemini | Ollama | Claude) ──► SQL ──► sql_guard ──► read-only SQLite ──► table + SQL in the UI
                                                  │                │
                                                  │                └─ authorizer, timeout, size caps
                                                  └─ one SELECT only, writes blocked, LIMIT forced
```

## How to run it

You need **Python 3.10 or newer** ([python.org](https://www.python.org/downloads/); tick *Add Python to PATH*
when installing). Check with `python --version`. Open a terminal **in the project folder**:
in File Explorer open the folder, click the address bar, type `cmd` or `powershell` and press Enter.

Everything below works in either **PowerShell** or **Command Prompt (cmd.exe)**. Where the two differ,
both versions are shown. (PowerShell shows `PS C:\...>` at the start of the line, Command Prompt shows `C:\...>`.)

### Step 1. Get an AI provider ready (pick one)

| Provider | Cost | What you need |
|---|---|---|
| **Gemini** (default) | Free tier | An API key from [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |
| **Ollama** | Free, runs on your computer | Install [ollama.com](https://ollama.com), start it, run `ollama pull qwen2.5-coder:7b` once. No key. |
| **Claude** | Paid | An API key from [platform.claude.com](https://platform.claude.com) plus some credit |

An **API key** is a secret password that lets this program call the AI on your account. Never paste it into a
file in this project, a screenshot, a chat or GitHub.

### Step 2. Set your key (every time you open a new terminal window)

The key is stored only in the window you set it in, and disappears when you close the window.

| | PowerShell | Command Prompt |
|---|---|---|
| Gemini | `$env:GEMINI_API_KEY="your-key"` | `set GEMINI_API_KEY=your-key` |
| Claude | `$env:ANTHROPIC_API_KEY="your-key"` | `set ANTHROPIC_API_KEY=your-key` |
| Ollama | nothing to set | nothing to set |
| Switch provider | `$env:ASK_DB_PROVIDER="ollama"` | `set ASK_DB_PROVIDER=ollama` |

- PowerShell needs the **quotes**. Command Prompt must **not** have quotes (they would become part of the key).
- Gemini is the default. You only need `ASK_DB_PROVIDER` to use `ollama` or `anthropic`.
- To check a key is set without printing it: PowerShell `if ($env:GEMINI_API_KEY) {"set"} else {"missing"}`,
  Command Prompt `if defined GEMINI_API_KEY (echo set) else (echo missing)`.
- To keep a key permanently instead, run `setx GEMINI_API_KEY "your-key"` once, then **open a new window**.
  Anyone using this computer account can then read it, so skip this on a shared computer.

### Option A. Using build.bat (easiest, Windows)

`build.bat` does all the setup for you. It does not need the virtual environment activated and it never
contains a key. It skips anything already done, so you can run it as often as you like.

| Goal | PowerShell | Command Prompt |
|---|---|---|
| Set up and test everything | `.\build.bat` | `build.bat` |
| Set up, then open the web app | `.\build.bat app` | `build.bat app` |
| Set up, then run the evaluation (prompts v1 and v2) | `.\build.bat eval` | `build.bat eval` |
| Remove caches and the database | `.\clean.bat` | `clean.bat` |
| Also remove saved eval reports | `.\clean.bat runs` | `clean.bat runs` |
| Remove everything generated: caches, database, eval reports and `.venv` (asks first) | `.\clean-all.bat` | `clean-all.bat` |

Typical first run (Gemini, PowerShell):

```powershell
cd C:\Users\User\source\repos\Personal\ask-the-database
$env:GEMINI_API_KEY="your-key"
.\build.bat app
```

What `build.bat` does, in order: creates `.venv` if missing, installs `requirements.txt`, builds
`db\resort.db` if missing, runs the 140 tests, prints the dry-run score (should say `20/20`). With `app` or
`eval` it first checks that the key for your provider is set, and stops with instructions if not.
Press **Ctrl+C** in the window to stop the web app.

`clean.bat` only deletes generated files. It never touches your code, prompts or `eval\results.md`, and it
asks before deleting `eval\runs` or `.venv`. Plain `clean.bat` keeps the `.venv` on purpose, because reinstalling
packages takes minutes while the database rebuilds in seconds. `clean-all.bat` is the full reset (it is the same
as `clean.bat all`). Stop the web app first, and type `deactivate` if your prompt shows `(.venv)`.
Copy your scores into `eval\results.md` before cleaning `eval\runs`.

### Option B. Using commands by hand

One-time setup (the first line is the same everywhere; the activate line differs):

```powershell
cd C:\Users\User\source\repos\Personal\ask-the-database
python -m venv .venv
```

| Activate the virtual environment | |
|---|---|
| PowerShell | `.venv\Scripts\Activate.ps1` (if it says scripts are disabled, run `Set-ExecutionPolicy -Scope Process Bypass` first) |
| Command Prompt | `.venv\Scripts\activate.bat` |

You will see `(.venv)` at the start of the line. Then:

```
pip install -r requirements.txt
python -m db.seed
pytest
python -m eval.run_eval --dry-run
```

The last two should print `140 passed` and `Accuracy: 20/20 = 100.0%`. No key is needed for them.

Then, in the same window, set your key (Step 2) and run any of these:

```
streamlit run app.py                              the web app (opens in your browser, Ctrl+C stops it)
python -m eval.run_eval --prompt v1               evaluation with the baseline prompt
python -m eval.run_eval --prompt v2               evaluation with the improved prompt
python -m eval.run_eval --history                 compare all saved runs
python -m eval.run_eval --prompt v1 --provider ollama     same, with another provider
python -m src.data_checks                         data-quality report
python -m src.llm --list-models gemini            model names your key can use
```

Each evaluation takes about 2 minutes on Gemini (it pauses between questions to respect the free limits)
and writes a failure report to `eval\runs\`. Every new terminal window needs two things again: activate
the `.venv` (Option B only) and set your key.

macOS/Linux: use `source .venv/bin/activate` and `export GEMINI_API_KEY="your-key"`. The `.bat` files are Windows only.

### The whole process, start to finish

Use this the first time, or after `clean-all.bat` for a completely fresh start. Examples are PowerShell;
in Command Prompt drop the `.\` and the quotes (`set GEMINI_API_KEY=your-key`, then `build.bat app`).

1. **Open a terminal in the project folder.**
   ```powershell
   cd C:\Users\User\source\repos\Personal\ask-the-database
   ```
2. **(Optional) Start completely fresh.** Type `deactivate` first if your prompt shows `(.venv)`, and stop the web app.
   ```powershell
   .\clean-all.bat
   ```
   Press `Y` when asked. This removes caches, the database, saved eval reports and the `.venv`.
3. **Set your API key** (Gemini shown; see Step 2 above for Claude, or Ollama which needs none).
   ```powershell
   $env:GEMINI_API_KEY="your-key"
   ```
4. **Set up everything and open the web app.**
   ```powershell
   .\build.bat app
   ```
   This recreates the `.venv`, installs packages, rebuilds the database, runs the 140 tests and opens the app in your
   browser. Ask an example question and check you get a table and the SQL. Press **Ctrl+C** to stop it.
5. **Run the evaluation** (about 4 to 5 minutes for v1 and v2 on Gemini).
   ```powershell
   .\build.bat eval
   ```
   It prints each question as PASS or FAIL, the accuracy for v1 and v2, and a history table.
   A `503 high demand` failure is Google being busy, not a wrong answer: rerun that question
   with `.venv\Scripts\python.exe -m eval.run_eval --prompt v1 --only q05`.
6. **Write it up.** Open the reports in `eval\runs\` (named by time, prompt and model). For each failed question decide
   the cause (wrong join, wrong date range, missing business rule, ambiguous question) and copy your scores and causes
   into `eval\results.md`.
7. **(Optional) Try to improve it with a new prompt.** Copy `prompts\v2.md` to `prompts\v3.md`, change one thing,
   then run it and compare. These commands use the `.venv` directly, so no activation is needed:
   ```powershell
   .venv\Scripts\python.exe -m eval.run_eval --prompt v3
   .venv\Scripts\python.exe -m eval.run_eval --history
   ```
   Always compare prompt versions run with the same provider and model.
8. **Before you clean again,** make sure your numbers are saved in `eval\results.md`. `clean.bat runs` and
   `clean-all.bat` delete the reports in `eval\runs`.

### If something goes wrong

| Message | What to do |
|---|---|
| `GEMINI_API_KEY is not set` (or Anthropic) | Set the key (Step 2) in the **same window** you are running from |
| `HTTP 404 ... model ... no longer available` | Model names get retired. Run `python -m src.llm --list-models gemini`, then set `ASK_DB_MODEL_GEMINI` to a working name |
| `HTTP 503 ... high demand` | Google is busy. Wait and rerun that question. Not a wrong answer, so don't count it as a failure |
| `HTTP 429` / quota or rate limit | Free-tier limit hit. Wait a minute, or run fewer questions with `--only q01 q02` |
| `Ollama is not running` | Start the Ollama app, then `ollama pull qwen2.5-coder:7b` |
| `Database not found` | Run `python -m db.seed` (or `build.bat`) |
| `No module named ...` | Activate the `.venv`, then `pip install -r requirements.txt` |
| `'python' is not recognized` | Reinstall Python and tick *Add Python to PATH*, then open a new window |
| `scripts is disabled on this system` (PowerShell) | `Set-ExecutionPolicy -Scope Process Bypass`, or use Command Prompt |

## Choosing an AI provider

Three interchangeable providers. Switch with the sidebar in the app, the `--provider` flag of the
eval, or the `ASK_DB_PROVIDER` variable. The default is `gemini`.

| Provider | Cost | Setup |
|---|---|---|
| `gemini` | Free tier (rate-limited) | Get a key at [aistudio.google.com/apikey](https://aistudio.google.com/apikey), then `$env:GEMINI_API_KEY="your-key"` |
| `ollama` | Free, runs on your computer, no key | Install from [ollama.com](https://ollama.com), start it, then `ollama pull qwen2.5-coder:7b` |
| `anthropic` | Paid (prepaid credit) | Create a key at [platform.claude.com](https://platform.claude.com), then `$env:ANTHROPIC_API_KEY="your-key"` |

```powershell
# Example: free, with Gemini
$env:GEMINI_API_KEY="your-key"
streamlit run app.py

# Example: free, local
ollama pull qwen2.5-coder:7b
python -m eval.run_eval --prompt v1 --provider ollama
```

Notes:

- **Model names change often.** If you get "model not found", list what your account can use:
  `python -m src.llm --list-models gemini` (or `ollama`), then pass `--model NAME` or set
  `ASK_DB_MODEL_GEMINI` / `ASK_DB_MODEL_OLLAMA` / `ASK_DB_MODEL_ANTHROPIC`.
- **Gemini's free tier has rate limits.** The eval waits 4 seconds between questions for Gemini and
  retries when it is told to slow down. Check Google's current limits; they change.
- **Small local models are weaker at SQL.** Expect a lower score from Ollama. That is useful: more
  failures to analyse, and a clearer before/after when you improve the prompt.
- Keys live in environment variables. They are never written to disk by this project, and they
  are sent in request headers, not URLs, so they cannot leak into error messages.
- `$env:NAME="value"` lasts until you close that PowerShell window. `.env.example` lists every setting.

| Command | What it does |
|---|---|
| `python -m db.seed` | Create the synthetic database (`--clean` skips the planted defects) |
| `streamlit run app.py` | The web UI |
| `python -m eval.run_eval --prompt v1` | Run the 20-question evaluation with a prompt version |
| `python -m eval.run_eval --provider ollama` | Same, with a different provider (also `--model`, `--only q04 q08`) |
| `python -m eval.run_eval --dry-run` | Self-test the scoring (the "AI" is the reference SQL); no key needed |
| `python -m eval.run_eval --history` | Accuracy of every saved run, side by side |
| `python -m src.data_checks` | Data-quality report: nulls, duplicates, orphan IDs, negative amounts, broken logic |
| `python -m src.llm --list-models gemini` | Model names available to you |
| `pytest` | Unit tests, including attempts to sneak `DROP TABLE` past the guard |

Other optional settings: `ASK_DB_PROMPT`, `ASK_DB_PATH`, `OLLAMA_HOST`, and `ASK_DB_TEMPERATURE=0`
for more repeatable eval runs (Ollama already defaults to 0).

```

db/
  schema.sql            Six tables: guests, bookings, restaurants, orders, retail_sales, events
  seed.py               Deterministic synthetic data generator
  data_quality_report.md  Output of the data checks on the seeded database
prompts/
  v1.md                 Baseline: schema + "return only the SQL"
  v2.md                 Adds dates, business rules, style rules, worked examples
src/
  config.py             Paths, limits, providers and default models
  prompt.py             Builds the system prompt from a versioned file
  llm.py                The only file that calls an AI (Gemini, Ollama, Claude)
  sql_guard.py          Validates generated SQL (layer 1 of the security model)
  db.py                 Read-only execution with authorizer and timeout (layer 2)
  pipeline.py           question -> AI -> guard -> database -> result (used by UI and eval)
  compare.py            Decides whether the AI's result matches the expected one
  data_checks.py        Data-quality queries and report
eval/
  questions.yaml        20 questions, each with a reference SQL that defines the right answer
  run_eval.py           Runs them, prints accuracy, writes a failure report to eval/runs/
  results.md            The write-up: accuracy per prompt version, every failure and its cause
tests/                  Guard, scoring, pipeline, provider and eval-set tests (no key needed)
```

## The data

One year of fake resort activity, 2025-07-01 to 2026-06-30: 500 guests, 3,000 bookings, 8
restaurants with 12,000 bills, 6 retail stores with 6,000 sales, and 60 events. It is generated
with a fixed random seed, so everyone gets the same database.

- **"Today" is fixed at 2026-07-01** (`src/config.py`), so "last month" always means June 2026 and
  the right answers never drift with the calendar.
- **A few defects are planted on purpose** (3 duplicate bills, 5 orphan guest IDs, 4 negative
  retail amounts, 15 missing emails, 2 missing event attendances) so the data-quality checks
  have something real to find. SQLite does not enforce foreign keys by default, which is how
  orphan IDs can exist. See `db/data_quality_report.md`.

## Security

Generated SQL is untrusted input: a model can be tricked by a crafted question or just be wrong.
Three independent layers, so no single bug is fatal:

1. **`src/sql_guard.py`** (text level). A small tokenizer, not a regex over raw text, so a keyword
   inside a string literal is not a false alarm. It allows exactly one statement, which must start
   with `SELECT` or `WITH`; rejects `INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/ATTACH/PRAGMA/...`
   and access to `sqlite_*` internals; strips comments; and **forces a `LIMIT`** (adds one, or
   caps an oversized one, including the `LIMIT offset, count` form).
2. **`src/db.py`** (database level). The file is opened with `mode=ro` plus `PRAGMA query_only`,
   an authorizer allows only reads, a progress handler aborts queries running longer than 5 s,
   and string/blob size is capped.
3. **`tests/test_sql_guard.py`**. About 40 attack strings (smuggled statements, comment tricks,
   writes hidden in a `WITH`, case games) must all be blocked, and separate tests bypass the
   guard on purpose to prove layer 2 still refuses writes.

API keys live in environment variables only. If you put this project in a git repo, make sure
`.env` and `db/resort.db` are in that repo's `.gitignore`, and never commit a real key.

## How the evaluation works

`eval/questions.yaml` holds 20 questions. Each has a **reference SQL** written by hand; it is run
against the database at eval time, so the expected answer is computed, never typed in. The AI's
result is compared to it by `src/compare.py`:

- column names are ignored, values must match; extra columns are fine, missing ones are not
- row order matters only for ranking questions (`ordered: true`)
- integers must match exactly; floats may differ only by rounding (34.5 or 35 match 34.52, 34 does not)

The questions are tagged by category (basic, date, aggregation, join, window, nulls,
business_rule, ambiguous) so you can see *what kind* of question fails. `q20` is ambiguous on
purpose ("most popular room type" could mean bookings, revenue or nights). Report it separately
when quoting a headline number.

**Workflow for improving the prompt**

1. Run `python -m eval.run_eval --prompt v1`. Note the accuracy.
2. Open the failure report in `eval/runs/`, find the cause of each failure, and record it in `eval/results.md`.
3. Copy `prompts/v1.md` to `prompts/v3.md` (or whatever is next), change one thing, re-run.
4. Never edit a version you have already evaluated. Otherwise the before/after is meaningless.
5. **Never paste eval questions into the prompt as examples.** That leaks the answers and inflates
   accuracy. A test in `tests/test_reference_queries.py` fails if you do.
6. Compare like with like: only compare prompt versions run with the **same provider and model**.

## Limitations

- Twenty questions is a coarse measure: each question is worth 5 points, and model output varies
  between runs. Run each prompt several times before trusting a small difference.
- The model sees the schema, not the data, and has no memory of earlier questions.
- The guard is intentionally strict and will reject some valid but unusual queries.
- Synthetic data is cleaner and smaller than real data; real-world accuracy would be lower.
- The Gemini and Ollama request formats are covered by tests with simulated servers, but model names
  and free-tier limits change, so check them if a call fails.
